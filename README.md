# 測定機器台帳

測定機器・標準器・試験機器の台帳を管理するツール。HTML・CSS・JavaScript だけで動き、データはブラウザの IndexedDB に保存する。

## 使い方

1. `index.html` をダブルクリックし、Edge で開く（サーバー・ビルドは不要）
2. 左のアイコン列の <b>サンプルデータ</b>（フラスコ）を開き、サンプルを読み込んで動きを確かめる
3. 試し終わったら同じパネルの「サンプルだけを消す」で消す（自分で登録したデータは残る）

詳しい操作は画面左下の <b>?</b>（取扱説明書、F1）を参照。

> **注意**：データはその PC のそのブラウザの中だけに保存されます。ほかの PC とは共有されず、ブラウザの閲覧データを消すと台帳も消えます。バックアップ（フロッピーのアイコン）から定期的に JSON に書き出してください。

## 画面の構成（レイアウト案 B「設置先ナビ」を採用）

| 領域 | 内容 |
|---|---|
| 上部バー | 検索（範囲：この設置先／すべて）、主ボタン「〇〇 に登録する」 |
| アイコン列 | 絞り込み・表示・分類と設置先・サンプルデータ・バックアップ・取扱説明書。パネルは最初は閉じている |
| 設置先 | 部 › 課 › ライン の木。配下を含む個体数、期限切れ・期限間近の件数 |
| 台帳 | 状態の件数ボタン（押すと絞り込み）、構成を開閉できる表 |
| 詳細 | 表に重ねて開く（1600px 以上の画面では並べる）。期限・項目・構成・写真・記録 |

レイアウト 5 案の比較と採用理由は `mockups/評価.md`、各案のモックは `mockups/index.html`。

## データの考え方

- **個体は内部 ID で識別**する。業務上の番号は分類ごとの「見分け方（識別キー）」で重複を調べる
  - 測定機器：設置先＋管理番号（使用中の中で重複不可。廃棄後の番号は再利用できる）
  - 標準器・試験機器：製造番号
- **構成（親・子・孫）は一緒に持ち運ぶ単位**（ブロックゲージセットと中のゲージ、試験機と力計など）。校正する側・される側の関係とは別に扱う
  - 子の校正日が空欄なら親の校正日を引き継ぐ。親の状態には構成の中で最も悪い状態を出す
  - 親を移動すると子も一緒に移動する
- **記録は追記していく**（登録・移動・校正・状態変更）。設置先の変更は「移動」として残る
- **分類ごとに項目を定義**する（文字・数値＋単位・選択肢・日付・長い文章）
- **校正に使った標準器（トレーサビリティ）は校正の記録に持たせる**（`events.standards`）。構成（親子）とは別の関係
  - 同じ校正で別のセット（セット全体・中のゲージとも）は使えない
  - 標準器が校正日の時点で有効だったかを、標準器自身の校正記録から判定する（期限切れでも登録はでき、警告を出す）
  - 標準器の詳細から「この標準器で校正した機器」を逆引きできる（標準器に問題が見つかったときの影響確認）
  - 標準器を削除しても、記録には名前の写し（`standardLabels`）が残る

| ストア | 内容 |
|---|---|
| `locations` | 設置先（id, name, parentId, order） |
| `categories` | 分類（kind, intervalMonths, identityKey, fields[]） |
| `assets` | 個体（categoryId, locationId, parentId, mgmtNo, serial, model, maker, lastCalDate, intervalMonths, state, props{}, note） |
| `events` | 記録（assetId, type, date, text, by。校正なら standards[], standardLabels[]） |
| `attachments` | 写真・書類（assetId, name, type, blob） |
| `meta` | 設定（画面の状態、前回の書き出し日など） |

サンプルの記録には `sample: true` が付き、これを手がかりにサンプルだけを消す。

```
js/data/db.js        IndexedDB の薄い包み（保存先を触るのはここだけ）

mockups/             レイアウト案 5 案と評価
```

## 機能の足し方

仲間を足すものはすべて登録簿になっており、`register()` を呼ぶだけで追加できる。

| 足したいもの | 登録簿 |
|---|---|
| 表の列 | `KK.columns` |
| 項目の型 | `KK.fieldTypes` |
| 大分類 | `KK.kinds` |
| 見分け方（識別キー） | `KK.identityKeys` |
| 記録の種類 | `KK.eventTypes` |
| 脇パネル | `KK.panelRegistry` |
| サンプルのパターン | `KK.samplePatterns` |
| 取扱説明書の章 | `KK.helpChapters` |

保存先を IndexedDB からサーバーに変える場合は、`js/data/db.js` と同じ形の関数を用意して差し替える。

## 動作確認

Node.js と Playwright がある環境で次を実行する（主要な作業経路 50 項目を確認）。

```bash
node tests/e2e.js
```

CDN に届かない環境では、`FA_DIR` に `@fortawesome/fontawesome-free` の展開先を指定するとアイコンを差し替えて確認できる。

## 残件

| 内容 | 状態 | 理由・再検討の条件 |
|---|---|---|
| 校正記録の入力画面（測定点ごとの値・許容差・合否、ラインまとめての校正日更新） | separate | 台帳を先に作る方針。データ構造（記録ストア）は用意済み |
| 帳票（印刷様式） | separate | 様式を受け取ってから作る |
| 標準器と被校正機器の関係（トレーサビリティ） | resolved | 台帳の「前回校正日」の校正に使った標準器として記録。校正記録の入力画面を作るときは同じ events.standards を使う |
| 実施者・承認者 | separate | 後で決める |
| 複数 PC での共有 | separate | 当面は 1 台＋JSON のバックアップ。共有が必要になったら保存先を差し替える |
| 列幅の手動変更 | resolved | 見出しの右端をドラッグ、ダブルクリックで自動に戻す。幅は保存。キーボードでの幅変更は未対応（低頻度のため） |
| 設置先の付け替え（ある課を別の部の下へ移す） | resolved | 設置先の編集の ⇄ から。置いてある機器は一緒に移る（移動の記録は残さない：物の場所は変わらないため） |
| 標準器として選べるのは大分類「標準器」の分類だけ | accepted | 力計などを標準器として使う運用が出てきたら、分類ごとに「標準器として使える」を持たせる |
| 1366px で絞り込みパネル・設置先・詳細を同時に開くと表が約 350px になる | accepted | 状態と番号は見え、詳細に全項目が出る。設置先は ≪ で畳める |
| Edge の実機確認 | blocked | 開発環境は Chromium。Edge も同じエンジンだが、file:// での IndexedDB を実機で確かめてほしい |
